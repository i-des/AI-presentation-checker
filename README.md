# AI Presentation Checker

AI-powered tool for automated quality control of presentations generated by Slidy.

The project uses a local **Qwen 3.6 35B A3B** model running through **LM Studio** to check presentations against a predefined design methodology.

The goal is to automate the first stage of quality control: instead of manually reviewing every generated presentation, the system checks the slides against the methodology and produces a structured result for further review.

## Overview

```text
                DESIGN METHODOLOGY
                        │
                        ▼
                Qwen + LM Studio
                        │
                        ▼
              Presentation slides
                        │
                        ▼
                 AI quality check
                        │
                        ▼
               Individual reports
                        │
                        ▼
              presentations_results.csv
                        │
                        ▼
              Manual review if needed
```

The model first receives the complete design methodology, including text rules and reference images.

After that, presentations are processed one by one using the same methodology.

## Features

- Loads a complete presentation design methodology into a local Qwen model
- Supports text rules together with reference images
- Uses LM Studio's stateful API to maintain the methodology context
- Checks presentations automatically
- Processes multiple presentations sequentially
- Generates individual analysis reports
- Produces a consolidated CSV with checking results
- Keeps the model and presentation data local

### Main files

| File | Purpose |
|---|---|
| `run_checker.py` | Main entry point. Runs the complete checking workflow |
| `load_methodology_batched.py` | Loads the design methodology into Qwen |
| `check_presentation.py` | Checks an individual presentation |
| `make_results_csv.py` | Collects individual results into a CSV file |
| `rules/` | Contains the design methodology and reference materials |
| `templates/` | Contains presentations to be checked |

## How It Works

### 1. Loading the methodology

`load_methodology_batched.py` reads the methodology from `rules/main_rules.json`.

The methodology is loaded chapter by chapter.

Depending on the chapter, the model receives:

- design rules;
- descriptions;
- good examples;
- bad examples;
- contextual images;
- template examples.

Images are encoded and sent to the model together with the corresponding descriptions.

The methodology is loaded using LM Studio's stateful API so that the model can continue the same conversation across multiple batches.

After the final batch, the resulting `response_id` is saved and can be reused for presentation checking.

### 2. Checking presentations

`check_presentation.py` checks one presentation at a time.

Presentation folders are stored inside:

```text
templates/
```

For example:

```text
templates/
├── Presentation_A/
├── Presentation_B/
└── Presentation_C/
```

The name of the presentation is taken directly from the folder name.

This means that no presentation name needs to be hardcoded into the checking script.

The checker loads the presentation data and slide images and sends them to the same Qwen conversation that contains the methodology.

### 3. Generating results

`make_results_csv.py` collects the individual results into:

```text
presentations_results.csv
```

The resulting table can be used to quickly filter presentations that require further manual review.

Example:

```text
Presentation,Result
Presentation_A,PASS
Presentation_B,FAIL
```

The project uses [LM Studio](https://lmstudio.ai/) to run the model locally.

The expected API endpoint is:

```text
http://127.0.0.1:1234/api/v1/chat
```

LM Studio must be running before starting the checker.

The project is configured to use:

```text
qwen/qwen3.6-35b-a3b
```

The model must be available in LM Studio.

## Methodology

The methodology is stored in:

```text
rules/
```

The main entry point is:

```text
rules/main_rules.json
```

This file defines the chapters that should be loaded into the model.

The corresponding chapter files and reference images should remain in the locations expected by the JSON files.

## Presentations

Each presentation should have its own folder inside:

```text
templates/
```

For example:

```text
templates/
├── Presentation_A/
│   ├── metadata.json
│   ├── slide_01.jpg
│   ├── slide_02.jpg
│   └── ...
│
└── Presentation_B/
    ├── metadata.json
    ├── slide_01.jpg
    ├── slide_02.jpg
    └── ...
```

The exact files required inside a presentation folder depend on the presentation export used by the project.

# Running the Checker

## 1. Start LM Studio

Open LM Studio and make sure the required Qwen model is loaded.

Start the local API server.

The project expects:

```text
http://127.0.0.1:1234
```

## 2. Open the project folder

Open a terminal in the project directory.

For example:

```bash
cd path/to/slidy-presentation-checker
```

## 3. Start the main script

Run:

```bash
python run_checker.py
```

The script will ask how to handle the methodology.

```text
1 — Load methodology again
2 — Use an existing response_id
```

### Option 1 — Load the methodology again

Choose:

```text
1
```

The system will run:

```text
load_methodology_batched.py
```

The complete methodology will be loaded into Qwen.

The final `response_id` is saved automatically and can then be used by the presentation checker.

### Option 2 — Continue an existing session

Choose:

```text
2
```

Then enter the existing `response_id`.

This allows the project to continue using a methodology that has already been loaded into the model without loading all the methodology again.

# Checking Presentations

After the methodology step, `run_checker.py` finds presentation folders inside:

```text
templates/
```

and sends them to:

```text
check_presentation.py
```

The presentation name is taken from the folder name.

For example:

```text
templates/
└── My_Presentation/
```

is automatically passed to the checker as:

```text
My_Presentation
```

The number of presentations processed during a run is controlled by:

```python
MAX_PRESENTATIONS = 2
```

in `run_checker.py`.

This can be increased when the system is ready to process a larger batch.

# Output

The project produces two types of results.

## Individual reports

Each checked presentation can have its own analysis report containing the detailed findings from the model.

These reports can be used for manual review and debugging.

## Consolidated CSV

After all presentations have been checked, the project runs:

```text
make_results_csv.py
```

and creates:

```text
presentations_results.csv
```

This provides a compact overview of the checking results across multiple presentations.

The CSV can then be filtered to identify presentations that require additional manual review.

# Local Processing

The project is designed around local processing.

The methodology, presentation images and analysis are sent to the locally running model through LM Studio.

The expected LM Studio endpoint is:

```text
http://127.0.0.1:1234
```

No cloud model API is required for the checking workflow.

```text
        ↓
```

# Why This Approach?

The main idea is to separate the process into two stages:

### Methodology

The model first receives the complete set of design rules and reference examples.

### Evaluation

The same model context is then used to evaluate generated presentations against those rules.

This makes it possible to apply the same evaluation framework across a large number of presentations instead of manually checking every presentation from scratch.
